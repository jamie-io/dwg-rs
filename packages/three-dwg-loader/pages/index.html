    Supported entities
    
				
    LibreDWG {{libredwg}} (patched, compiled in) decodes the file. ACIS solids are tessellated by dwg-rs itself, without an ACIS kernel. Tested DWG versions: R14 to 2018 (AC1014 to AC1032).
    
				
    
					
    DWGglTF
    
					
						
    3DSOLID, BODY, REGION, SURFACE (ACIS)Triangles from the B-rep (planes, cones, spheres, tori, NURBS); deviation below 0.1 mm, but not finer than 0.1 % of the body size
    
						
    MESH, polyface and polygon meshes, 3DFACE, SOLID, TRACETriangles with smoothed normals
    
						
    LINE, ARC, CIRCLE, ELLIPSE, polylines, SPLINELines; surfaces when they have a thickness or width
    
						
    INSERT, MINSERTOne node per instance, mesh shared per block
    
						
    Layer and ByBlock colors, MATERIAL, embedded OFML material archivesPBR materials, textures
    
						
    INSUNITSScaled to meters, Z-up to Y-up
    
					    
				
    
				
    ACIS data: SAT text (R14 to 2004), SAB in the entity (2007 and later), SAB in the data-storage section (2013 and later).
    
			
    
			
    
				
    Limitations
    
				
      
					
    • Not converted: text, dimensions, hatches, leaders, viewports, lights, raster images. They are listed as skipped in the summary.
      • 
					
    • Model space only. Paper space entities are counted in a warning.
      • 
					
    • Xrefs are not resolved (skipped, with a warning).
      • 
					
    • Dynamic blocks: the state they were saved in.
      • 
					
    • MESH: level-0 cage, no smoothing.
      • 
					
    • ACIS faces without usable surface data are filled from their boundary and reported.
      • 
					
    • Drawings without units (R14, or INSUNITS 0) are read as meters. If a drawing is 1000 times too large, set Units to mm.
      • 
					
    • Textures referenced by path: open the images together with the DWG. Embedded OFML materials include theirs.
      • 
					
    • Per drawing at most 10 million triangles, 1 million block instances and 60 million polyline points. The browser holds the whole drawing in memory.
      • 
					
    • gltf2dwg writes one texture per material (base color) and no animation, skins, cameras, lights or vertex colors. LibreDWG's writer for 2010 and later is new; check important files in your CAD program.
      •

    The samples on this page are from this set. Selecting one runs the same comparison on the WebAssembly output (Properties, Check). Native and WebAssembly builds can differ slightly in floating point, so triangle counts may differ too.
    
				
    These are single shapes, not complete drawings. For a drawing that converts wrongly, please open an issue with the converter summary, and the file if you can share it.
    
			
    
			
    
				
    Usage
    
				
    Command line (Rust 1.85 or later and a C compiler; all dependencies are in the repository):
    
				
    git clone https://github.com/jamie-io/dwg-rs
cd dwg-rs && cargo build --release
target/release/dwg2gltf drawing.dwg              # writes drawing.glb
target/release/dwg2gltf drawings/ -o out/        # a whole folder
target/release/gltf2dwg model.glb -o model.dwg   # glTF to DWG
    
				
    three.js loader (not on npm yet): build the module with scripts/build-wasm.sh, then serve packages/three-dwg-loader/src and wasm side by side.
    
				
    import { DWGLoader } from './three-dwg-loader/src/DWGLoader.js';

const drawing = await new DWGLoader().loadAsync( 'drawing.dwg' );
scene.add( drawing );
    
				
    C interface: dwg2gltf.dll / libdwg2gltf.so, with Delphi bindings. Details in the README.
    
				
    Commands on this page: OPEN, ZOOM, ISO, TOP, FRONT, RIGHT, EDGES, WIRE, DIMS, LINES, UNITS, VERSION, SAMPLE, CHECK, GLB, HELP.
