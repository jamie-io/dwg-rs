# libredwg-sys

[LibreDWG](https://www.gnu.org/software/libredwg/)'s DWG decoder and encoder,
vendored and compiled into a static library, with Rust bindings. Used by
`dwg2gltf` and `gltf2dwg`; building it needs only a C compiler (no
autotools, no LibreDWG install, no network).

Version: a snapshot of upstream master,
[`4f2aef33865e0d5bf3774acc439953fba15dea3e`](https://github.com/LibreDWG/libredwg/commit/4f2aef33865e0d5bf3774acc439953fba15dea3e)
(2026-11-05), after 0.14. No release has the fixes since 0.14 yet:
`libredwg/NEWS` lists them under "0.14.1", among them the security fixes in
the R2004/R2007 section readers (CVE-2026-63474, GHSA-c8cq-gr5h-7c6j,
GHSA-2m5x-9p64-6m3f, GHSA-pcp5-hv9w-8f78) and the 3DSOLID double free
(GHSA-6v3v-3gmq-63v4). The snapshot also has the MESH subdivision level fix
(PR #1435) and the R2007+ material/plot style flag order fix (#1436).

## Contents

| Path | What |
| --- | --- |
| `libredwg/` | The library sources of the snapshot without DXF/JSON, patched (GPL-3.0-or-later, see `libredwg/COPYING`); `NEWS` and `COMMIT` say what it is |
| `patches/` | Patches applied on top of the snapshot (see below) |
| `shim/` | `dwg2gltf_decode` / `dwg2gltf_encode` (file images in memory), `dwg2gltf_text` (text fields as UTF-8), `dwg2gltf_new` (a drawing with AutoCAD/ODA header values) |
| `build.rs` | Writes `config.h` for the target and compiles `libredwg/src` and `shim/` with the `cc` crate |
| `src/bindings.rs`, `src/bindings_wasm32.rs` | Generated by `gen-bindings.sh` (bindgen) for 64-bit targets and for wasm32, checked in |
| `vendor.sh` | Recreates `libredwg/` from the commit's GitHub archive (checks its SHA-256) |

Supported targets: 64-bit little-endian, and `wasm32-wasip1` (for the
three.js loader; the C compiler is wasi-sdk's clang, found through
`$WASI_SDK_PATH`). Checked on macOS arm64, Linux arm64 and x86_64 (gcc),
Windows x64 (mingw-w64, run under Wine) and wasm32-wasip1 (wasi-sdk 34). The
bindings' layout assertions are checked at compile time on every target.

LibreDWG is not reentrant: the decoder, encoder and `dwg_free` keep state in
static variables (loop counters, the current version). `libredwg_sys::lock()`
returns a process-wide guard; hold it across every call and until the
`Dwg_Data` is freed.

## Patches

- `patches/libredwg-acds-keep-section.patch`: keeps the decompressed
  `AcDsPrototype_1b` section in `Dwg_Data.acds.raw`. R2013+ solids store their
  ACIS data there and LibreDWG does not attach it to the entities (upstream
  issue #1411, open).
- `patches/libredwg-add-mesh-material.patch`, for writing:
  `dwg_add_MESH`, `dwg_add_MATERIAL`, `dwg_add_xdictionary` and bulk XRECORD
  appends; XRECORDs get their owner; MATERIALs of drawings built with the add
  API are no longer replaced by placeholders; the encoder's count limits
  (0xff00 / 65534 / 20000) are raised to 16M; objects over 0x7fff bytes no
  longer lose their last 3 bytes (the handles) when the size field grows.
  Details: docs/IMPLEMENTATION_NOTES.md section 9.2.
- `patches/libredwg-r2010-section-sizes.patch`, for writing: the R2010+
  header variables and classes sections get the size field AutoCAD and ODA
  write (data after the high size word, high word 0). Without it ODA-based
  readers refuse every written file ("CRC does not match"). Details:
  docs/IMPLEMENTATION_NOTES.md section 9.2.
- `patches/libredwg-entity-material.patch`, for writing: the encoder keeps
  an entity's explicit material handle (material flags 3) in drawings built
  with the add API. Upstream still drops it without `DEBUG_CLASSES`, which
  only mattered as long as the flags were read in swapped order (0.14 wrote
  the material through the plot style fields).
- `patches/libredwg-embedded-mtext-reactors.patch`: the embedded MTEXT of
  R2010+ ATTRIB/ATTDEF (new in master) read a corrupt reactor count's worth
  of handles past the end of the handle stream, which hung the decoder on a
  damaged file (a bit-flipped `2018/Dynblocks.dwg`, which 0.14 refused at
  once). The loop now stops at the first handle it cannot read.
- `patches/libredwg-surface-acis.patch`: EXTRUDEDSURFACE, LOFTEDSURFACE,
  REVOLVEDSURFACE and SWEPTSURFACE are debugging classes upstream, kept as
  UNKNOWN_ENT without `DEBUG_CLASSES`. R14 to R2010 drawings store their
  ACIS data inside the entity, so it was lost and the surfaces converted to
  nothing. They are now decoded as far as their ACIS data and handles; the
  full specs stay behind `DEBUG_CLASSES` (NURBSURFACE too: no sample yet).

Dropped with the move from 0.14: the MESH subdivision-level patch (merged
upstream as PR #1435).

## Maintenance

```sh
./vendor.sh          # after changing a patch or the LibreDWG commit
./gen-bindings.sh          # after changing include/dwg.h or shim/shim.h (needs bindgen-cli 0.73 and libclang)
./gen-bindings.sh wasm32   # the same for wasm32 (needs $WASI_SDK_PATH; run both)
```

To move to a newer commit: set `COMMIT` and `SHA256` in `vendor.sh`, rebase
the patches (apply them to the new tree in a scratch git repository, fix the
rejects, export each with `git diff`), run both scripts, update
`PACKAGE_VERSION` in `build.rs`, and compare the BricsCAD measurements
(`tests/bricscad/README.md`) and test results of the old and the new build.
