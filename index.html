What it reads

LibreDWG (0.14.1, patched and compiled in) decodes the file. dwg-rs builds the geometry from it, including the ACIS solids, which it tessellates itself: no CAD kernel is involved.

In the DWGIn the glTF
3DSOLID, BODY, REGION, SURFACE (ACIS)Triangles from the B-rep: planes, cones, spheres, tori and NURBS, less than 0.1 mm from the true surface, but never finer than 0.1 % of the body's size
MESH, polyface and polygon meshes, 3DFACE, SOLID, TRACETriangles with smoothed normals
LINE, ARC, CIRCLE, ELLIPSE, polylines, SPLINELine segments; with a thickness or a width, surfaces
INSERT, MINSERTOne node per instance, sharing the block's mesh
Layer and ByBlock colors, MATERIAL objects, embedded OFML material archivesPBR materials and textures
INSUNITSScale to meters; Z-up turned to glTF's Y-up

The ACIS data is read in all three ways DWG stores it: as SAT text (R14 to 2004), as SAB binary in the entity (2007 and later) and in the data-storage section of 2013 and later.

What it leaves out

  • Text, dimensions, hatches, leaders, viewports, lights and raster images. The summary lists them as skipped.
  • Layouts (paper space). Only model space is converted; a warning counts what stays behind.
  • External references. An xref is skipped and named in a warning.
  • Dynamic blocks are converted in the state they were saved in.
  • A MESH is drawn as its unsmoothed cage.
  • ACIS faces without usable surface data are filled from their boundary; the summary says so.
  • Drawings without units (all R14 files, and others set to “unitless”) are taken as meters. Pick the units above if a drawing comes out 1000 times too large.
  • Texture images that a DWG names by path: open them together with the DWG. Embedded OFML materials carry their own.
  • Limits per drawing guard against damaged files: 10 million triangles, 1 million block instances, 60 million polyline points. The page holds the whole drawing in memory.

The reverse direction, gltf2dwg, writes one texture per material (base color), and no animation, skins, cameras, lights or vertex colors. LibreDWG's writer for 2010 and later is new: check important files in your CAD program.

How it is tested

The repository holds 546 drawings made in BricsCAD V27 by scripts: 78 shapes, each saved in 7 DWG versions from R14 to 2018. For each shape the right answer is known: its extents and, where they apply, its area, its volume and which way its faces point. They come from a formula where there is one, otherwise from BricsCAD. The last report, for the command line build of converter 78c0118:

525match: extents within 0.2 mm, area and volume within 1 %
21thinner than 1 mm, checked by their extents only
0differ from the right answer
0fail to convert

LibreDWG reports recoverable decode errors on 369 of these files; their geometry still matches. The samples on this page come from the suite. Their panel runs the same comparison in your browser, on what the WebAssembly module made of the file. It can differ from the command line build in the last digits, and so in the number of triangles, as both round floating point a little differently.

Single shapes test the geometry, not whole drawings, which fail in their own ways. If one of yours converts wrongly, open an issue with the converter summary, and the file if you can share it.

Use it

Command line tools, built from source with Rust 1.85 or later and a C compiler. Everything else is in the repository.

git clone https://github.com/jamie-io/dwg-rs
cd dwg-rs && cargo build --release
target/release/dwg2gltf drawing.dwg              # writes drawing.glb
target/release/dwg2gltf drawings/ -o out/        # a whole folder
target/release/gltf2dwg model.glb -o model.dwg   # and back

In three.js, as a loader. It is not on npm yet: build the module with scripts/build-wasm.sh and serve packages/three-dwg-loader/src and wasm next to each other, as this page does.

import { DWGLoader } from './three-dwg-loader/src/DWGLoader.js';

const drawing = await new DWGLoader().loadAsync( 'drawing.dwg' );
scene.add( drawing );

From C, Delphi and other languages through dwg2gltf.dll and its C interface. The README covers all three.
